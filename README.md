# 방과후 곳간 🧮

방과후학교 강사비 예산의 잔여 소요를 자동 계산해, 추경 시 **반납(감액)·증액 예상액**을 바로 알려주는 웹 서비스입니다.

> 이 문서는 도구 소개와 더불어, **AI(Claude Code)와 협업해 며칠 만에 실무 도구를 만든 과정·기술 선택·시행착오**를 기록합니다. 팀원들과 "학교 업무 도구를 AI로 어떻게 만들 수 있는가"를 이야기하기 위한 자료입니다.

- **접속 주소**: <https://bin7335.github.io/gotgan/> — 예시 데이터로 둘러보기: [?sample](https://bin7335.github.io/gotgan/?sample)
- **배포**: GitHub Pages (main 브랜치 push 시 자동 배포)
- **PRD**: 요구사항과 의사결정 이력 전체를 버전(v0.1~v0.13)으로 기록한 문서를 별도 관리

---

## 1. 어떤 문제를 푸는가

방과후학교 담당자는 추경 시기마다 "연말까지 강사비가 실제로 얼마나 더 나갈지"를 계산해 남는 예산을 반납하거나 부족분을 증액 요구해야 합니다. 이 계산이 어려운 이유:

- 강좌마다 요일·시수·단가가 다르고, 행사·재량휴업으로 수업이 빠지는 날이 계속 생김
- 휴강은 보강되기도 하고(지출 유지), 그냥 소멸하기도 함(지출 감소)
- 교통비는 시간이 아니라 **출강 1일당** 지급, 같은 강사가 하루 2강좌면 1회만
- 추경 서류는 총액이 아니라 **산출내역 단위**로 작성

기존에는 달력을 짚어가며 엑셀로 수기 계산했는데, 30분 이상 걸리는 데다 휴강일을 하나라도 놓치면 반납액이 틀어져 재추경 사유가 됩니다. 이 도구는 강좌·휴강일·예산만 넣으면 즉시 계산합니다.

핵심 산식:

```
남은 수업 횟수 n = (기준일 이후 수업 요일 날짜 수) − 휴강 + 보강
잔여 지출 = n × (시수 × 시간당 단가) + 출강일수 × 일당 교통비
추경 예상액 Δ = (기정예산 − 집행액) − Σ 강좌별 잔여 지출   # 양수=반납, 음수=증액
```

## 2. 주요 기능

| 기능 | 설명 |
|---|---|
| 절차형 설정 마법사 | 학교 정보 → 예산 → 강좌 → 휴강일·방학 → 확인. 언제든 "설정 다시하기"로 재진입 |
| 강좌 일괄 등록 | 학기중/여름방학/겨울방학 서브탭, 표 형태로 여러 강좌 한번에 |
| 휴강일 목록 입력 | 날짜·사유만 등록. 법정 공휴일(내장 데이터, 범위 초과 시 경고) 자동 반영 + 개별 해제 |
| **세출예산 엑셀 가져오기** | K-에듀파인 세출예산집행현황(.xls) 업로드 → 키워드 추천 → 담당자 체크 → 유목화(강사비/교통비/재료비/기타) |
| **운영계획서 hwpx 가져오기** | 시간표(격자형·목록형)를 읽어 강좌 목록을 신규/변경/폐강 후보로 현행화 |
| 산출내역별 추경 예상 | 추경 서류 단위(산출내역)로 반납/부족을 각각 표시 |
| 예산 활용 가이드 | 월별 지급 예정표 + 규칙 기반 조언(수업 증설 가능 횟수, 부족 해소 조건 등) |
| 보고서 | 결재 첨부용 A4 인쇄 뷰 + CSV 다운로드 |

**개인정보 설계**: 모든 데이터(업로드한 엑셀·hwpx 포함)는 **브라우저 안에서만** 처리되고 localStorage에 저장됩니다. 서버 전송이 전혀 없어, URL만 공유하면 다른 학교 담당자도 자기 데이터로 즉시 사용할 수 있고 학교 간 데이터가 섞일 수 없습니다.

## 3. 기술 스택과 왜 그렇게 골랐는지

| 선택 | 이유 |
|---|---|
| React + TypeScript + Vite | 표준적인 조합. 타입이 예산 계산 실수를 컴파일 단계에서 잡아줌 |
| 서버 없음 (정적 사이트 + localStorage) | 학교 전산망 환경 고려, 개인정보 부담 제로, 배포·운영 비용 제로. "계정 없이 5분 안에 첫 결과" 원칙 |
| 계산 로직을 순수 함수로 분리 (`src/core/`) | UI 없이 vitest로 검증. 테스트 41개 — PRD의 검증 시나리오가 그대로 테스트 케이스 |
| SheetJS (동적 로드) | K-에듀파인 구형 .xls(바이너리 BIFF)까지 브라우저에서 파싱 |
| JSZip | hwpx = ZIP + XML(OWPML) 구조라 압축만 풀면 표 데이터 접근 가능 |

| GitHub Pages + Actions | push만 하면 테스트 → 빌드 → 배포 자동. 별도 서비스 가입 불필요 |

날짜는 전부 `'YYYY-MM-DD'` 문자열(사전순 = 시간순)로 다루고 타임존은 Asia/Seoul 고정, 금액은 정수(원)만 사용해 부동소수점 오차를 원천 차단했습니다.

## 4. 개발 방식 — AI와 PRD 주도로

전 과정을 Claude Code와 대화하며 진행했습니다. 실제로 효과가 컸던 방식:

1. **PRD 먼저, 코드 나중**: 첫 대화에서 PRD v0.1을 만들고, 결정이 날 때마다(단가 체계, 교통비 규칙, 수익자부담 제외...) PRD에 "결정 기록"으로 남겼습니다. v0.13까지의 버전 이력이 곧 프로젝트 의사결정 로그입니다.
2. **계산 코어를 테스트와 함께 먼저** (M1): UI 없이 산식+테스트부터. PRD에 적은 검증 시나리오("반납 320,000원")가 통과하는 걸 확인한 뒤 UI를 올렸습니다.
3. **실물 파일로 파서 검증**: 에듀파인 엑셀과 운영계획서 hwpx는 문서만 보고 짐작하지 않고, 실제 파일을 fixture로 받아 구조를 분석한 뒤 파서를 만들고 그 파일로 테스트를 고정했습니다.
4. **사용 → 피드백 → 즉시 반영 루프**: "캘린더 입력 번거로움", "일괄 등록 필요", "방학 따로", "절차대로 진행되게" 같은 실사용 피드백이 당일 반영됐습니다.
5. **AI 도그푸드 QA** (dogfooding: 자기 제품을 직접 써보며 검증하는 것): 별도 AI 에이전트가 완성된 앱을 실제로 조작하며 QA 리포트(이슈 7건: 모바일 깨짐, 문구 불명확, 공휴일 표기 불일치, 접근성)를 생성 → 그 리포트를 다시 개발 세션에 넣어 수정. **AI가 만들고 AI가 검수하는 루프**가 실제로 동작했습니다.

## 5. 파일 파싱 기술 상세 — 엑셀(xls/csv)과 hwpx

이 프로젝트의 기술적 핵심입니다. 학교 업무 파일(에듀파인 엑셀, 한글 문서)을 **서버 없이 브라우저 안에서** 구조화 데이터로 바꾸는 방법을 기록합니다.

### 5-1. K-에듀파인 세출예산집행현황 (.xls) — SheetJS

**파일 형식의 함정부터.** K-에듀파인이 내려주는 `.xls`는 요즘 엑셀(xlsx = ZIP+XML)이 아니라 **1990년대 BIFF 바이너리 포맷**(Composite Document, EUC-KR 코드페이지 949)입니다. 직접 파싱은 사실상 불가능하고, [SheetJS(xlsx 패키지)](https://sheetjs.com/)가 BIFF·xlsx·csv를 모두 읽어줍니다. 참고로 기관 시스템이 주는 `.xls` 중에는 확장자만 xls인 HTML 테이블도 흔한데(열어서 매직 바이트 확인 필요), 이 파일은 진짜 BIFF였습니다.

```ts
const XLSX = await import('xlsx')                    // 429KB라 동적 로드 (첫 화면 번들에서 제외)
const wb = XLSX.read(await file.arrayBuffer(), { type: 'array' })
const rows = XLSX.utils.sheet_to_json(wb.Sheets[wb.SheetNames[0]],
  { header: 1, defval: '' })                         // 2차원 배열로 — 이후는 순수 함수의 영역
```

`header: 1` 옵션이 핵심입니다. 열 이름 추측을 시켜놓으면 병합·다단 머리글에서 깨지므로, **그냥 2차원 배열로 받아서 구조 해석은 직접** 합니다. 이렇게 하면 파싱 로직(`parseBudgetRows`)이 SheetJS와 분리된 순수 함수가 되어 실물 파일로 단위 테스트할 수 있습니다.

**계층 복원 — 들여쓰기가 데이터다.** 세출예산 목록은 이런 구조입니다:

```
    학생복지운영                                      ← 세부사업 (들여쓰기 4칸)
       [초]통폐합기금(방과후학교운영)                  ← 세부항목 (7칸)
          운영수당 | 방과후학교강사료 | 12,950,000 | 4,640,000 | ...   ← 실제 예산 행 (10칸)
```

트리 구조가 별도 열이 아니라 **첫 열의 앞 공백 개수**로 표현되어 있습니다. 파서는 스택을 하나 들고 내려가면서, 산출내역이 비어 있는 행은 그룹(공백 수가 얕아지면 스택 pop, 깊어지면 push), 산출내역이 있는 행은 잎(leaf)으로 처리해 `세부사업 > 세부항목 > 목 > 산출내역` 경로를 복원합니다. 이 경로가 중요한 이유: **"[목]강사료"라는 같은 이름이 다른 사업에 두 번 나오기 때문**에, 경로 전체를 키로 써야 "지난번 선택 기억 → 재매칭"이 안전합니다.

머리글 위치도 하드코딩하지 않습니다. '산출내역'이라는 셀을 찾아 그 행을 머리글로 삼고, '예산현액'·'원인행위액'으로 시작하는 열을 탐색합니다 — 학교마다 앞쪽 안내 행 수가 달라도 동작합니다. 금액은 `"12,950,000"` 같은 문자열에서 숫자만 남겨 정수(원)로 변환합니다.

**CSV는 덤으로 지원됩니다** — SheetJS가 같은 API로 읽기 때문에 추가 코드가 없습니다.

### 5-2. 운영계획서 (.hwpx) — JSZip + 좌표 기반 표 복원

**hwp와 hwpx는 완전히 다른 물건입니다.** 구형 `.hwp`는 한컴 비공개 바이너리 포맷이라 브라우저 파싱이 사실상 불가능합니다(오픈소스 시도들이 있지만 불완전). 반면 `.hwpx`는 **국가표준(KS X 6101, OWPML) — ZIP 안에 XML**이 들어 있는 구조라, 압축만 풀면 문서 내용에 접근할 수 있습니다:

```
운영계획서.hwpx (= ZIP)
├── Contents/section0.xml   ← 본문 (표 포함)
├── Contents/header.xml     ← 스타일 정의
├── Preview/PrvText.txt     ← 텍스트 미리보기
└── META-INF/, settings.xml ...
```

```ts
const JSZip = (await import('jszip')).default
const zip = await JSZip.loadAsync(await file.arrayBuffer())
const xml = await zip.file(/Contents\/section\d+\.xml/)[0].async('string')
```

XML에서 표는 `<hp:tbl>` → 행 `<hp:tr>` → 셀 `<hp:tc>` → 텍스트 `<hp:t>`로 들어 있고, **결정적으로 셀마다 좌표와 병합 정보가 명시**되어 있습니다:

```xml
<hp:tc>
  <hp:cellAddr colAddr="2" rowAddr="3"/>   <!-- 이 셀은 (2,3)에서 시작 -->
  <hp:cellSpan colSpan="1" rowSpan="4"/>   <!-- 세로로 4행 병합 -->
  ... <hp:t>토탈공예A(미술실)</hp:t>
</hp:tc>
```

HTML 표처럼 "병합된 자리는 셀이 아예 없어서" 위치를 추측해야 하는 문제가 없습니다. 이 좌표 덕분에 병합이 뒤엉킨 시간표도 기하학적으로 정확히 복원됩니다. 전체 XML 파서를 쓰지 않고 필요한 태그만 정규식으로 뽑는데, 대상 태그 구조가 단순·규칙적이라 충분했고 의존성도 줄었습니다.

**표 형태 자동 인식 — 두 종류의 시간표.** 실물 운영계획서에는 형태가 다른 표 2개가 있었습니다:

- **격자형** (교시×요일 주간표): 머리글에 '교시'와 요일(월~금)이 있으면 격자형으로 분류. 파싱 알고리즘:
  1. 머리글 행에서 요일 셀들의 열 범위를 구함 (월=2~3열, 화=4~5열, ... — colSpan으로 요일당 과목/학년 2열)
  2. 첫 열에서 숫자(교시) 셀들의 행 범위를 구함 (5교시=3~6행, 6교시=7~14행, ... — rowSpan이 제각각)
  3. 요일 범위의 **첫 열**에 있는 텍스트 셀만 강좌 후보로 봄 (옆 열은 학년·인원)
  4. 강좌 셀의 행 범위와 교시 행 범위의 **겹침(overlap)** 으로 몇 교시 수업인지 결정
  5. 같은 강좌명을 요일별로 집계 → `{강좌명, 요일들, 하루 교시 수}` 완성
- **목록형** (구분/강사/요일/시간 열): 병합 정보로 2차원 행렬을 만들어 **병합 셀 값을 아래로 채우고(fill-down)** — "영어놀이A"가 2행에 걸쳐 병합되어 있으면 두 행 모두에 채움 — 강좌명으로 묶어 요일 합집합·행 수(=교시 수)를 계산합니다.

**필터 규칙 — 실물에서만 배울 수 있는 것들:**
- `정규수업`, `오후돌봄`, `늘봄교실` 셀은 강좌가 아님 → 제외
- `예술아놀자C:오후돌봄` → 콜론 앞부분만 강좌명으로 채택, `오후돌봄:늘봄교실` → 통째로 제외
- `1,2,4`, `1~2`, `15명`, `전학년` 같은 학년·인원 표기 제외
- **셀 텍스트에 임의 공백이 섞임** (`오후 돌봄`, `로봇과학 A`) → 모든 비교 전에 공백 제거 정규화. 이거 안 하면 "오후 돌봄"이 강좌로 등록되고, "로봇과학 A"와 "로봇과학A"가 다른 강좌가 됩니다
- 요일 파싱의 함정: `월요일,수요일`에서 글자 단위로 요일을 찾으면 **'월요일'의 '일'이 일요일로 매칭**됩니다 → '요일'이라는 단어를 먼저 제거한 뒤 남은 글자(월, 수)만 매칭

**현행화(diff)**: 추출 결과를 기존 강좌와 이름 기준(공백 무시)으로 대조해 신규 / 변경(요일·시수·강사) / 폐강 후보로 나누고, 담당자가 체크한 것만 반영합니다. 폐강은 삭제가 아니라 **종료일 앞당김**으로 처리해 이력을 보존합니다.

### 5-3. 공통 원칙

1. **파싱 결과는 항상 사람이 확정** — 파일 형식은 언제든 변할 수 있고, 예산은 틀리면 안 되는 숫자라서
2. **실물 파일을 fixture로 테스트 고정** — "방과후학교강사료 = 12,950,000원이 정확히 나오는가"를 테스트로 박아두면, 파서를 고칠 때 회귀를 즉시 잡음
3. **무거운 라이브러리는 동적 import** — SheetJS(429KB)·JSZip은 가져오기 버튼을 누를 때만 로드
4. **모든 처리는 브라우저 안에서** — 예산·강사 정보가 외부로 나가지 않음

## 6. 시행착오 기록 (공유 포인트)

팀에서 비슷한 도구를 만들 때 참고할 만한, 실제로 겪은 문제들입니다.

### ① OneDrive 폴더에서 개발하지 말 것
처음에 OneDrive 동기화 폴더 안에서 시작했다가 node_modules 동기화 부하와 **파일 잠금**(esbuild.exe, rollup 네이티브 모듈이 프로세스에 물려 폴더 이동·삭제 실패)으로 고생했습니다. 로컬 경로(`D:\dev`)로 옮기고 잔여 프로세스를 찾아 종료해야 했습니다. **개발 폴더는 처음부터 동기화 폴더 밖에 두세요.**

### ② "완전 자동"의 함정 — 자동 추천 + 사람 확정 패턴
세출예산에서 방과후 예산을 자동 추출할 때, 키워드 매칭만 믿으면 틀립니다. 실제 데이터에서 **"방과후학교강사기관부담금"은 '강사'가 들어가지만 강사비가 아니고**, 키워드에 안 걸리는 강사비 항목도 존재했습니다. 예산에서 오차는 곧 서류 오류라, "키워드로 추천 → 담당자가 체크로 확정 → 선택을 기억해 다음부터 자동 재매칭" 패턴으로 확정했습니다. 이 패턴은 hwpx 시간표 현행화(신규/변경/폐강 후보 diff)에도 재사용했습니다.

### ③ 도메인 지식이 파서보다 중요
- 집행현황의 금액이 지출액이 아니라 **원인행위액(계약·품의 확정액)** 기준이라는 것 — 모르면 조용히 틀린 숫자가 나옵니다. 화면에 기준을 명시하고 수동 조정을 열어뒀습니다.
- 교통비는 시간당이 아니라 **출강 1일당**, 같은 강사 같은 날 복수 강좌는 1회만 — 이런 실무 규칙이 산식의 대부분입니다. 규칙 하나가 확정될 때마다 테스트로 고정했습니다.

### ④ hwp였으면 못 했다 — hwpx의 재발견
운영계획서가 구형 .hwp(비공개 바이너리)였다면 브라우저 파싱은 사실상 불가능했지만, **hwpx는 ZIP+XML이라 압축 해제 후 표 접근이 가능**합니다. 결정적으로 hwpx 표는 셀마다 좌표(`cellAddr`)와 병합(`cellSpan`) 정보를 갖고 있어, 병합이 뒤엉킨 교시×요일 격자 시간표도 정확히 복원됩니다. 함정도 있었습니다: 셀 텍스트에 임의 공백이 섞여("오후 돌봄", "로봇과학 A") 필터를 뚫고 들어와, **공백 제거 정규화**를 이름 비교 전반에 적용해야 했습니다.

### ⑤ UI는 만든 사람 기준이 아니라 절차 기준으로
- 월 캘린더 뷰를 공들여 만들었지만 실사용 피드백은 "날짜만 입력하게 해달라" → 폐기하고 목록 입력으로. **만든 기능을 버리는 결정**이 제품을 나아지게 했습니다.
- 탭에서 찾아다니는 구조 → "절차대로 진행되게"라는 피드백으로 설정 마법사(①~⑤ 단계) 도입.
- 대시보드도 카드가 9개까지 쌓이자 같은 숫자가 3번 반복 → "질문에 답하는 순서"(결론 → 경고 → 흐름 → 서류용 상세 → 조언)로 재배치하고 입력·상세는 접었습니다.

### ⑥ 조언 기능에 AI API를 쓰지 않은 이유
"예산을 어떻게 쓰면 좋을지 조언" 기능은 LLM 호출 없이 **계산 규칙**으로 만들었습니다(반납액 ÷ 회당 단가 = 증설 가능 횟수 등). 근거가 투명하고, 비용이 없고, 오프라인에서도 동작하며, 예산 숫자가 외부로 나가지 않습니다. 생성형 AI가 필요한 곳과 규칙으로 충분한 곳을 구분하는 게 중요했습니다.

### ⑦ 기타
- **공휴일 데이터**: 대체공휴일 규칙이 헷갈려 내장 데이터로 시작하되, 내장 범위를 넘는 강좌 기간에는 경고를 띄워 "조용한 누락 → 반납액 왜곡"을 방지. 장기적으로는 공공데이터포털 특일 API 연동 예정.
- **QA 리포트의 가치**: AI 도그푸드가 잡은 "공휴일 표기(2025~2026)와 실제 목록(2027-01-01 포함)의 불일치" 같은 이슈는 만든 사람은 못 보는 종류였습니다.
- **fixture 프라이버시**: 실물 검증 파일에는 강사 실명·학교 예산이 있어 `.gitignore`로 제외하고, 파일이 없으면 해당 테스트가 자동 스킵되게 해 CI를 살렸습니다.

## 8. 개발/실행 방법

```bash
npm install
npm run dev        # 개발 서버 (localhost:5173)
npm test           # 테스트 (fixture 없으면 실파일 검증 스킵)
npm run typecheck  # 타입 검사
npm run build      # dist/ 정적 빌드
```

URL 파라미터: `?sample`(예시 데이터), `?setup`(설정 절차 강제 진입), `?tab=courses|closed|report|settings`

배포는 main 브랜치에 push하면 GitHub Actions가 테스트 → 타입 검사 → 빌드 → GitHub Pages 배포를 자동 수행합니다.
